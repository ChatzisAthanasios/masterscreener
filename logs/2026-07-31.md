### Approximations vs the original Finviz definitions (apply to every v2 session)

- gap-up-momentum: `ta_gap_u4` approximated by change ≥ 4% at capture time (the opening gap
  itself is not separately observable).
- unusual-volume: `ta_sma20_pa` approximated by price > MA50 (no MA20 in the cloud source).
- top-losers: RSI is daily RSI as of the prior close, not intraday.
- most-volatile: `ta_volatility_wo5` approximated by |change| ≥ 5%; `sh_opt_option` not
  verifiable in cloud.
- Relative volume = today's volume / 20-day average volume (Finviz uses its own definition).
- Candidate pool = top-20 gainers + top-20 losers + top-20 most-active (fresh) rather than a
  full-universe screen. A stock qualifying for a screen while sitting outside all three lists
  would be missed; for these momentum screens that is rare by construction, but it is a bias

## Why v2 exists

The original design fetched finviz.com screener pages by URL. Verified on 2026-07-31 from
inside Anthropic's cloud:

- `finviz.com/screener.ashx` and `/screener?…` (every variant, including the patterns
  finviz's own robots.txt whitelists) → refused by the cloud fetcher: ROBOTS_DISALLOWED.
- `finviz.com/quote?t=X` → ignores the ticker parameter for the cloud fetcher and serves an
  unrelated page (PAYX) every time.
- finviz.com homepage → fetchable, but serves the previous session's cached values to the
  cloud fetcher (verified identical numbers 85 minutes apart mid-session).
- stockanalysis.com list pages → also bot-cached, BUT a cache-busting query parameter
  (`?nocache=<random>`) returns fresh intraday data. Statistics pages are fresh.

This is why the 2026-07-30 scheduled runs produced nothing: the sessions had no fetchable
data source (and the cloud routine environment itself never demonstrably executed).

The two scheduled routines created 2026-07-30 via the web UI ("Finviz Screener ENTRY run",
"Finviz Screener EXIT run") could not be disabled from this session (created via http_api);
they remain enabled but harmless — they push nothing. The owner should delete them in the
routines UI. Replacement scheduled tasks using the v2 pipeline are being created from the
Cowork session of 2026-07-31.

## EXIT RUN / RESULTS — scored retroactively on 2026-08-01

The scheduled exit run never executed, and no exit snapshot existed for this date. Scored
retroactively from the **local machine** on Saturday 2026-08-01.

Exit prices are each ticker's 2026-07-31 **16:00 ET close**. Because 07-31 was a Friday and
the capture ran on the Saturday, the quote sources still served that session's close — the
same prices a 16:05 ET run would have used, so scoring is valid per the runbook design.

Sources and verification:

- Bulk quotes via `finviz.com/screener.ashx?v=111&t=<tickers>` (runbook EXIT step 2), two
  pages, 20 rows + 17 rows. Note this URL **is** fetchable from the local machine; it is only
  ROBOTS_DISALLOWED from the cloud fetcher, which is what forced the v2 pipeline above.
- Spot-verified against stockanalysis.com for NVDA, REPL and WETO — all three matched the
  Finviz price exactly, each stamped "At close: Jul 31, 2026, 4:00 PM EDT". This confirmed
  both the session date and that the extraction was not fabricating values.

  decimals, which below ~$0.50 is worth several percent of the price and manufactures returns
  that are artifacts of rounding. RITR read as `0.06` → +28.76%; its true close of `0.0565`
  is +21.24%. Corrected from stockanalysis.com: LBGJ 0.0187, ONFO 0.0790, WETO 0.0900,
  RITR 0.0565, YYAI 0.1200, KWM 0.0837, VSEE 0.0787, MGN 0.0736, ZBAO 0.2001, MBRX 0.4000,
  GCTK 0.4770. This moved `top-losers` from +5.23% to +1.47%.
